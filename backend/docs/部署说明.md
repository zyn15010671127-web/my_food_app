# 运行与部署说明

## 本机演示

本机已验证环境：Windows x64、Python3.14.8、SQLite。先解压ZIP，再双击`run.bat`。脚本依次创建`.venv`、离线安装锁定依赖、复制`.env.example`、执行Alembic迁移并初始化演示数据，最后监听`127.0.0.1:8010`。

首次安装需要磁盘空间与目录写入权限。Python须提前安装；离线依赖包不包含Python安装程序。完整依赖已锁定，接口文档资源也由本机提供。若机器不是Windows x64/Python3.14，使用联网安装对应平台依赖。

数据库、图片和开发JWT密钥写入`data/runtime/`，该目录未随提交包分发。重启服务会继续读取此目录，因此不会自动丢失记录或改变密钥。不要在服务器运行时移动该目录。

本地开发可以设置`AUTO_CREATE_TABLES=true`，但数据库结构升级应使用迁移。启动脚本会先执行迁移；不要将旧练习版数据库直接替换到新提交版中，因为表名和字段已有扩展。原练习版目录完整保留，可独立运行。

## 配置项

| 配置 | 作用 |
| --- | --- |
| APP_ENV | development或production |
| DATABASE_URL | SQLite或PostgreSQL SQLAlchemy连接地址；留空为本地SQLite |
| DATA_DIR | 图片、SQLite与本地密钥目录，未设置时为项目内data/runtime |
| JWT_SECRET_KEY | JWT签名密钥；开发模式可自动生成，生产必须显式配置 |
| SEED_DEMO_DATA | 是否初始化演示账号及数据 |
| AUTO_CREATE_TABLES | 是否允许开发模式自动补建表 |
| ACCESS_TOKEN_MINUTES | 登录凭证有效分钟数，默认30 |
| CORS_ORIGINS | 逗号分隔的前端来源白名单 |
| RATE_LIMIT_ENABLED | 进程内基础限流开关 |
| ENABLE_EXTERNAL_AI | 是否允许调用外部模型 |
| AI_BASE_URL | 兼容Chat Completions协议的HTTPS基础地址，含版本路径 |
| AI_API_KEY | 服务端模型密钥，禁止放到Flutter客户端 |
| AI_CHAT_MODEL | 文字模型名称，由所选供应商提供 |
| AI_VISION_MODEL | 支持图片输入的模型名称，由所选供应商提供 |

`DB_HOST`、`DB_PORT`、`DB_USER`、`DB_PASSWORD`、`DB_NAME`为Docker提供另一种连接配置，避免手动拼接含特殊字符的密码。当`DATABASE_URL`已设置时优先使用该地址。

## 连接外部模型

在项目根目录`.env`中设置：

```dotenv
ENABLE_EXTERNAL_AI=true
AI_BASE_URL=https://你的兼容服务地址/v1
AI_API_KEY=你自己的服务端密钥
AI_CHAT_MODEL=供应商提供的文字模型名
AI_VISION_MODEL=供应商提供的视觉模型名
```

基础地址末尾不包含`/chat/completions`，程序会追加。请求中还需设置`allow_external_processing=true`，才会发送对应的问题、最近会话或图片；默认不外传。不要把示例占位值当成可用账号。

识别流程为：上传图片→获得`image_id`→创建识别任务→核对候选名称并选择食物编号/克数→确认写入。模型候选名称未匹配食物库时`food_id=null`，客户端应引导手动搜索，不直接记录未知营养值。

视觉输出要求JSON候选名称与置信度；不支持该格式的供应商会触发手动降级。文字接口返回会话编号、回答、执行模式和知识来源。外部失败不会伪造成功结果。

## 使用本地PostgreSQL

先创建空数据库，并在`.env`中设置实际连接：

```dotenv
DATABASE_URL=postgresql+psycopg://diet:URL编码后的密码@127.0.0.1:5432/diet
```

然后在项目目录执行：

```powershell
.\.venv\Scripts\python.exe scripts\init_db.py
.\.venv\Scripts\python.exe -m uvicorn main:app --host 127.0.0.1 --port 8010
```

`scripts/init_db.py`应用迁移；开发演示模式开启时还会填充演示数据。`docs/postgresql-schema.sql`是从同一份迁移生成的参考DDL，不要在已经应用Alembic迁移的数据库中重复执行。

## Docker Compose部署

本机未安装Docker，本节配置已静态检查，未声称已完成容器运行验收。

在`.env`中设置随机长密钥和数据库密码，例如通过`python -c "import secrets; print(secrets.token_hex(32))"`自行生成后写入：

```dotenv
JWT_SECRET_KEY=你生成的随机长密钥
POSTGRES_PASSWORD=你自己的数据库密码
CORS_ORIGINS=https://你的前端域名
```

启动：

```text
docker compose up --build -d
docker compose exec api python scripts/create_admin.py --username administrator
```

第二条命令会交互要求管理员密码，不把密码写到命令行。生产容器关闭演示账号与自动建表，入口先运行Alembic迁移。API默认只绑定宿主机回环端口8010，公网访问应由HTTPS反向代理接入。数据库不映射宿主机端口，数据保存在命名卷中。

生产模式下要自行导入核实后的食物与菜谱，不能使用演示账号、默认口令或把公开演示数据当成经过检测的营养库。进程内限流适用于单实例；扩展多个实例时需使用共享限流存储。

## Flutter联调

同机浏览器或桌面客户端使用`http://127.0.0.1:8010`。Android模拟器访问宿主机时一般使用`http://10.0.2.2:8010`；真实手机联调需在可信局域网内启动监听地址`0.0.0.0`，客户端改为电脑的局域网地址。先确认设备网络可达，再排查接口。

登录后将Token保存在客户端的安全存储中，后续个人接口携带`Authorization: Bearer <Token>`。401时清除失效凭证并引导重新登录。上传采用multipart字段`file`；图片读取同样需要登录请求头。Flutter Web的实际来源端口应加入`CORS_ORIGINS`，原生App通常不受浏览器CORS限制。调试用HTTP网络策略只用于开发环境，正式发布使用HTTPS。

## 数据备份

SQLite：停止服务后备份整个`data/runtime`，其中同时包含数据库、密钥和图片；恢复时保持一致。PostgreSQL：使用`pg_dump`备份数据库，同时备份图片卷。JWT密钥改变后现有登录凭证失效，属于预期行为。

接口`GET /api/account/export`导出当前用户的结构化数据，不含密码哈希、密钥与图片二进制；图片可逐张通过私有图片接口读取。`DELETE /api/account`需要当前密码，会删除用户关联记录、目标、会话和图片。
